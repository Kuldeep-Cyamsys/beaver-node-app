Beaver Node Android integration guide

Development handoff for embedding node configuration inside another Android app. Contract baseline: Android app 0.2.0 and ESP32 firmware 0.2.0, HTTP API v1. Prepared 21 October 2026.

The Android app connects directly to the ESP32 access point. The ESP32 is the backend for all APIs in this guide. No cloud login, Raspberry Pi API, MQTT connection or internet access is involved in node configuration.

Host Android app
  -> selected Beaver Wi-Fi Network
  -> HTTP 192.168.4.1:80 /api/v1/*
  -> ESP32 settings, RTC, live sample and flash storage

STM32 -> UART -> ESP32 -> E52 mesh -> Pi gateway -> MQTT
                     (separate data delivery path)

Scope and identity

device_id identifies the physical ESP32. node_id is the configurable logical radio address. target is the gateway-connected radio address. Do not replace these with the Pi gateway ID or MQTT Thing name. The node API still returns the ESP32 identity even though later gateway MQTT payloads use gateway identity.

All examples are illustrative, not captured live responses. The guide describes the inspected code. Confirm the firmware installed on each field device before depending on optional 0.2.0 fields.

Connection and Android network handling

Wi-FiSSID Beaver; password 12345678; WPA2-PSK; channel 1; maximum 2 clients.

Boot and shutdownAP starts off. Physical button enables it; POST ap/disable turns it off. No AP auto-expiry or credentials-setting API.

Automatic connection sequence

1. Ask the operator to enable the node AP. Request the runtime Wi-Fi permission. Construct WifiNetworkSpecifier with SSID Beaver and WPA2 passphrase 12345678. Request a TRANSPORT_WIFI Network and remove NET_CAPABILITY_INTERNET.

2. Android displays its connection consent dialog. onAvailable provides a Network object. Keep that object and open each HTTP connection through Network.openConnection. Do not use the cellular/default network for node requests.

3. GET status, validate device_id and an eight-element channels array, then GET config. Show the device identity before editing. An associated Wi-Fi network alone is not proof of a working Beaver API.

4. On network loss, clear the selected Network and live state, stop polling, and show disconnected. Keep completed local downloads accessible. Release callbacks when the feature is closed or its owner is destroyed.

Manual fallback

Open Android Wi-Fi settings, join Beaver, accept the no-internet connection, return to the app and select Use Wi-Fi. The existing implementation selects the first available Wi-Fi Network and verifies the API. A host app should handle multiple available Wi-Fi networks explicitly rather than assuming the first is correct.

Multiple nodes use the same SSID. Enable one AP at a time when practical, and verify device_id on every new connection. Do not silently reuse edited settings when switching to another node.

Android project and transport contract

Current source: native Java Activity, Java 17, minSdk 29 (Android 10), compileSdk/targetSdk 36, versionName 0.2.0, versionCode 2. Build uses Gradle 8.13 and Android Gradle Plugin 8.13.2. These are the inspected project settings, not requirements to change the host app framework.

Connect / read timeout7000 ms / 15000 ms. Read timeout is an inactivity bound, not a whole-download deadline.
RedirectsDisabled. Existing client accepts only HTTP 200 as success.

Use UTF-8. JSON keys are case-sensitive. Send numeric integers as numbers and radio_enabled as a JSON boolean. Firmware rejects unknown or duplicate setting fields, arrays, nested request objects and malformed bodies. Do not echo an entire GET config response into PUT config.

This local API has no token, login or per-user authorization. Host-app roles can hide features but do not prevent another AP client from calling the API. There are no implemented CORS/OPTIONS handlers for browser-hosted clients; use a native networking bridge for a web-based host app.

Error envelope is not standard JSON

Most handler errors are sent with the ESP-IDF HTTP error helper as text. Do not expect {"error":...} for all failures. Preserve HTTP status and a bounded text body. A connection close or timeout may occur instead of an HTTP response. Do not show credentials in diagnostics.

CaseMeaning and app action
400 Bad RequestMalformed/invalid input or export range. Display details, correct fields or refresh storage bounds. Do not loop retries.
500 Internal Server ErrorAllocation, RTC, persistence or export-start failure. Preserve message; refresh relevant state before retrying.
503 Service UnavailableCSV export busy or AP shutting down. Wait for other export to finish or reconnect before retrying.
404 or unsupported methodWrong API path, method, device or firmware. Treat as compatibility error; do not assume gateway endpoints exist.
Timeout / disconnectFor GET, reconnect and retry deliberately. For PUT, outcome is unknown: GET/read back before retry. For AP disable, disconnect can be expected.
Malformed 200 responseProtocol/compatibility error. Never declare success solely from the status code; validate body or CSV completion.

The JSON helper sends application/json and Cache-Control: no-store for status/config. RTC success currently does not explicitly set application/json, despite returning JSON text. Parse its successful body rather than requiring that response MIME type. AP-disable success explicitly sets application/json.

Status field meanings and quality flags

FieldsMeaning
device_id / firmware_version12 lowercase hex characters for physical ESP32 identity. firmware_version is available in 0.2.0; tolerate absence on older firmware.
time_valid / utcRTC validity and Unix UTC seconds. utc is 0 when invalid; never display it as an actual 1970 measurement.
sample_age_ms / staleAge since accepted STM32 sample; -1 if none. Stale at age >= 60000 ms or no sample.
BatteryPercentage / PcbTemperatureNumber or JSON null. Missing fields on older firmware are unavailable. Battery 0 is valid; temperature 0 is valid. Null also occurs when stale.
frames / bad_frames / uart_overflowsAccepted frames, rejected input and UART overflow diagnostics. Treat as firmware runtime counters, not stored-log totals.
missed_logs / radio_retriesLogging failure/skipped scheduling diagnostics and radio retry counter; not a count of outstanding records.
first_sequence / last_sequenceRetained sequence bounds, 0 when empty. Holes can exist; last-first+1 is not an exact retained-record count.
delivery_cursorDurably acknowledged radio delivery position for the current stream/target/PAN context. Not MQTT cloud confirmation.
record_capacity / storage_faultMaximum storage capacity in records, and storage failure indicator. Capacity is not occupancy.
ap_on / radio_ready / radio_errorAP activity, E52 configuration readiness and radio diagnostic code. Readiness does not prove successful gateway reception.

Per-channel status is a bitmask

Bit valueMeaning
0OK only when no bits are set.
1Frequency fault.
2NTC resistance fault.
4Stale data.
8No sample received.

Combine flags with bitwise tests. Status 7 = frequency fault + NTC fault + stale; 15 additionally means no sample. Unknown bits should be displayed as unknown flags. Stale channel numbers may still contain older readings: do not treat them as fresh because they look plausible.

Frequency 0 represents faulty/disconnected input; resistance -255 represents failed NTC measurement. This contract cannot distinguish NTC open circuit from short circuit. Do not label them separately without a future firmware change.

Saving settings and handling concurrent edits

Cross-field validation

Router role 0 requires node_id 0..32767. Terminal role 1 requires node_id 32768..65534. node_id must differ from target. app_ack_ms must be at least route_ms + link_ack_ms + 5000. When changing role, send the matching node ID in the same request.

PUT /api/v1/config
Content-Type: application/json

{"interval_s":300,"node_id":3,"target":1}

HTTP 200 -> full resulting config object

Only the supplied writable fields are changed. Firmware validates the merged configuration, commits it to NVS and then updates the in-memory config. A changed configuration increments revision. An unchanged patch, including an empty object, returns the existing config without increasing revision.

Existing app save flow

1. Load config before showing fields. Keep a baseline. Build a patch only for user-edited values. Validate input types/ranges and cross-field rules; show a confirmation of the patch.

2. Immediately before PUT, GET config again and validate the intended patch merged into the fresh result. Send only the patch, not the full merged object. Replace the UI baseline with the returned full config.

3. Changes to radio parameters apply asynchronously. Show Settings saved separately from Radio ready. Monitor status and delivery_cursor to distinguish module configuration from end-to-end delivery.

There is no ETag, If-Match or revision precondition. The fresh GET reduces stale-edit risk but does not make the following PUT atomic against another client. For a host app, detect baseline changes and ask the operator to resolve conflicting edits; do not present this as firmware-enforced locking.

Exact handler error text

ResponseBody / trigger

A changed interval restarts the logger countdown. Logging is interval-based, not aligned to quarter-hour boundaries. Changing RTC time does not restart that monotonic schedule. Raw channel values are retained; there is no configurable spike-filter feature.

This example matches the previously working gateway profile: address 1, PAN 4660, channel 15, 62.5K and 22 dBm. It is not a universal default. Read the actual gateway configuration and use unique node addresses. The node default channel 18 differs from that tested gateway channel 15.

radio_errorMeaning
0No current error; check radio_enabled and radio_ready too.
1E52 configuration failed.
2Stored record read failed.

4Gateway ACK timeout / unsuccessful send path. radio_ready may remain true.

The delivery cursor is scoped to stream, target and PAN. Changing target or PAN can invalidate the current cursor and replay retained history to that destination. Warn the operator. Downloading CSV does not advance this cursor. Node radio delivery and Pi MQTT delivery are separate mechanisms; the later gateway rule about not replaying uploaded MQTT records does not change this node behaviour.

A successful PUT means settings were saved, not that E52 accepted them. A growing delivery cursor is evidence of acknowledged radio progress; it does not prove AWS storage. There is no HTTP endpoint for radio ping, per-packet ACK history, RSSI, hop count, topology or route-table editing.

RTC synchronization and AP shutdown

PUT /api/v1/time

PUT /api/v1/time
Content-Type: application/json

{"utc":1792540800}

HTTP 200
{"ok":true}

The request must contain exactly one field named utc, an integer Unix timestamp in seconds from 1704067200 through 4102444799 inclusive (2024 through 2099 UTC). Milliseconds, numeric strings, fractions, extra keys and null are invalid.

For phone synchronization, generate epoch seconds at confirmation time. Do not add the local time-zone offset: epoch seconds already represent UTC. Display times in the phone zone separately. For manually entered local time, convert using the selected zone; the existing app rejects ambiguous and nonexistent daylight-saving times.

After success, GET status and verify time_valid and utc against the phone clock. Use a small tolerance for network/processing delay. Do not treat a successful request as proof of backup-power retention; test that on hardware.

FailureResponse
Invalid body or timestamp400: utc must be integer Unix seconds, 2024..2099
RTC write failure500: ESP-IDF error name returned by esp_err_to_name.
Connection lostUnknown outcome. Reconnect and read utc before retrying.

POST /api/v1/ap/disable

POST /api/v1/ap/disable
(no body required)

HTTP 200, application/json
{"ok":true,"disable_after_ms":1000}

Confirm with the operator first. The firmware sends the response, queues shutdown, waits about one second, cancels any active export and waits for its worker to finish before stopping HTTP and Wi-Fi. Actual disconnection can therefore take longer than 1000 ms.

Stop app polling and release the requested Wi-Fi Network after acknowledgment. Treat subsequent network loss as expected. The current app clears live/config state; saved phone files remain. The physical GPIO34 button is required to enable AP again; there is no remote AP-enable route while Wi-Fi is off.

AP shutdown does not save unsent form edits. Save and verify each configuration first. AP shutdown does not erase logs or disable the independently running logger/radio tasks.

CSV endpoint and record format

GET /api/v1/logs.csv
GET /api/v1/logs.csv?from=1&to=72

HTTP 200
Content-Type: text/csv
Content-Disposition: attachment; filename=beaver-logs.csv

The query range is inclusive. With no query, the firmware snapshots current bounds. If a query is supplied, both from and to are required as decimal uint64 strings: from > 0, from <= to and to <= current last_sequence. A start before current first_sequence is rejected. The client should validate both bounds against a fresh status response.

Current export has 34 columns in exactly this order. The legacy format has the same first 32 columns, without the two auxiliary fields. Actual header is one line; it is wrapped below only for readability.

kind,sequence,stream,utc,node_id,age_ms,time_flags,
F1,F2,F3,F4,F5,F6,F7,F8,
R1,R2,R3,R4,R5,R6,R7,R8,
S1,S2,S3,S4,S5,S6,S7,S8,
config_revision,BatteryPercentage,PcbTemperature
Column groupMeaning
kindDATA for records. ERROR lines are control/error records, not measurements.
sequence / streamDecimal uint64 values. Use stream plus sequence to identify a stored record.
utc / time_flagsUnix seconds; time_flags bit 1 means invalid RTC timestamp. Invalid utc is 0.
node_id / config_revisionLogical node ID and configuration revision captured when that log was created.
age_msAge of the source sample when logged. No sample uses 4294967295, unlike live status which uses -1.
F1..F8 / R1..R8Integer Hz / integer ohms. Fault and stale values must be interpreted with S flags.
S1..S8Same channel quality bitmask as live status.
BatteryPercentageInteger 0..100 or blank when unavailable.
PcbTemperatureCelsius decimal with two digits in export, or blank when unavailable.

Blank auxiliary CSV cells must remain unavailable, never zero. Records from the older flash format can have blank auxiliaries even in a 34-column export. Temperature is PCB temperature only; NTC R fields remain resistance.

The endpoint does not pin flash pages. Ring-buffer overwrite can race an export. A normal HTTP 200 start is therefore not proof that a complete file was delivered.

Reliable downloads and export errors

Completion algorithm used by the app

1. GET status; capture stream_id, first_sequence and last_sequence. For full export, explicitly request those nonzero bounds. For an empty store (last_sequence 0), use logs.csv without a query and accept a header-only file.

2. Stream into a temporary .partial file. Validate the exact 32- or 34-column header; each row must be DATA with the matching column count. Reject ERROR rows. Preserve trailing blank cells when splitting CSV.

3. Require each row to have the captured stream, a strictly increasing sequence within the requested range, and numeric values. Duplicate/descending records fail. The existing parser checks battery 0..100 and finite PCB temperature -327.67..327.67 when present. It checks other data columns as integer values, not every physical range.

4. At EOF require the final sequence to equal the requested to. Holes within the range are allowed; row count need not equal to-from+1. A custom ending sequence must correspond to a retained valid record. If it ends on a hole, the current app rejects the export as incomplete.

5. Only after validation succeeds, rename to beaver-<device_id>-<phone_epoch_ms>.csv in app-private files. Delete the partial on failure. Keep only the newest 100 rows in memory for the preview while counting all DATA rows.

Status or stream contentHandling
400: Use ?from=<sequence>&to=<sequence>, within available rangeInvalid/oversized query or out-of-range end. Refresh bounds and correct input.
400: Start sequence no longer retainedOldest requested data was overwritten. Inform operator; obtain new bounds.
503: Export unavailable or AP shutting downAnother export or shutdown is active. Avoid parallel exports.
500: Cannot start exportExport worker could not start. Some async allocation failures can instead close the connection.
ERROR,export_cancelledShutdown interrupted export. Discard the partial file.
ERROR,range_overwritten_during_exportRing advanced beyond needed data during export. Discard partial; refresh bounds.
ERROR,storage_read_failedStorage read error. Discard partial; inspect storage health.
EOF before requested final sequenceIncomplete export even if HTTP was 200. Do not save as complete.

There is no resume token or date-range filter API. Restart a failed snapshot/range download after refreshing bounds. The export is not a background service in the existing app. Keep the feature open; process termination may require retry. Deleting a phone copy never deletes device records.

Embedding the feature in another app

Recommended module boundaries

For Flutter, React Native or a WebView host, put Wi-Fi selection and Network-bound HTTP in an Android native bridge. A generic fetch/Dart HTTP call is not automatically bound to the local-only Network returned by WifiNetworkSpecifier. Return parsed objects and file handles/events to the UI.

// Transport pattern already used by DeviceApi
HttpURLConnection c = (HttpURLConnection) selectedNetwork
    .openConnection(new URL(
        "http://192.168.4.1/api/v1/status"));
c.setRequestMethod("GET");
c.setConnectTimeout(7000);
c.setReadTimeout(15000);
c.setInstanceFollowRedirects(false);

Suggested connection states: disconnected, permission required, connecting, verifying device, ready, unavailable, shutting down. Keep a separate operation state for saving, syncing and exporting. A radio error must not be presented as a Wi-Fi connection failure.

Serialize device operations; suspend Live polling during writes/downloads. Never perform network or CSV work on the UI thread. Clear stale screen values on disconnect or mark them explicitly as last read. Handle process recreation rather than relying only on orientation handling.

The existing ContentProvider authority is com.cyamsys.beaver.logs and is hard-coded in sharing logic. Change both manifest and URI construction for the host applicationId to avoid installation conflicts. Grant temporary read permission; do not expose arbitrary private files.

Acceptance tests and known limitations

Wi-Fi with mobile data onAPI calls use Beaver Wi-Fi despite no internet. Permission denial/cancel offers manual fallback.
Node identitySwitch between two nodes with the same SSID; no old config or readings are silently reused.
Live data qualityEight correct channel mappings; 0 vs null preserved; stale at 60 s; status 7 and 15 decoded as flags.
Settings validationReject strings/fractions/out-of-range values; update role and ID together; reject node equal target and short ACK timeout.

Limitations to preserve or improve explicitly

No app-account authentication in the current node backend; no HTTPS, API key, OTA, AP credential update, log erase, NTC beta conversion, exact live log count, node STA mode or remote AP enable. None should be represented as implemented features.

Read-only config/security fields and firmware_version are optional on older firmware. The Android Health footer still contains the old 0.1.0 text even though Gradle identifies the app as 0.2.0; use build metadata, not that footer, when labelling the integrated release.

CSV download validation is stronger than reopening saved files: loadLog performs lighter parsing. If the host app will import externally supplied CSV files, run full validation before viewing them. Keep downloaded previews bounded and do not interpolate faulty readings in charts.
